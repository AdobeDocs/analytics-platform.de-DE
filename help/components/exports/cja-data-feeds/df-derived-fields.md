# Anwenden von Datenumwandlungen für Daten-Feeds

{{release-limited-testing}}

Sie können Ihre Daten-Feed-Daten mit einer der folgenden Methoden umwandeln:

* [Einstellungen der Datenansichtskomponente](/help/data-views/component-settings/overview.md), Verwendung von

* [Abgeleitete Felder](/help/data-views/derived-fields/derived-fields.md)

* SQL

Die Methode, die Sie wählen, ist manchmal eine Frage der Präferenz. In der folgenden Tabelle werden die Kompromisse verglichen.

## Datenumwandlungsmethoden vergleichen

In der folgenden Tabelle werden die Vor- und Nachteile jeder Methode im Allgemeinen verglichen.

| Methode | Vorteile | Nachteile |
| --- | --- | --- |
| **Einstellungen der Komponente** | <ul><li>Wird zum Zeitpunkt der Berichterstellung angewendet, bevor Ihr Daten-Feed bereitgestellt wird.</li><li>Dieselbe Logik gilt konsistent sowohl für Analysis Workspace als auch für Ihre Daten-Feed-Ausgabe.</li><li>Verbraucht keines der begrenzten abgeleiteten Felder Ihres Kontos.</li><li>Einige Transformationen, wie Persistenz und Metrik-Deduplizierung, sind in SQL schwer zu replizieren, und Persistenz ist derzeit auch mit einem abgeleiteten Feld nicht möglich.</li></ul> | <ul><li>Nur für den spezifischen Satz von Einstellungen verfügbar, den jede Komponente unterstützt - nicht so flexibel wie das Erstellen benutzerdefinierter Logik mit einem abgeleiteten Feld.</li><li>Ob eine Einstellung die Daten-Feed-Ausgabe überhaupt beeinflusst, wird noch für einige Einstellungen bestätigt. Siehe Tabelle unten.</li></ul> |
| **Abgeleitete Felder** | <ul><li>Wird zum Zeitpunkt der Berichterstellung angewendet, bevor Ihr Daten-Feed bereitgestellt wird.</li><li>Dieselbe Logik gilt konsistent sowohl für Analysis Workspace als auch für Ihre Daten-Feed-Ausgabe.</li><li>Unterstützt eine flexiblere, benutzerdefinierte Logik als jede einzelne Komponenteneinstellung, z. B. verkettete bedingte Regeln.</li><li>Einige Umwandlungen, insbesondere solche, die von einer Bereichseinstellung abhängen oder eine URL analysieren, sind in SQL schwer zu replizieren.</li></ul> | <ul><li>Dies verursacht zusätzlichen Verarbeitungsaufwand, der sich auf die Leistung der Daten-Feed-Bereitstellung auswirken kann.<!--Under a future usage-based pricing model, this could also add cost.--></li><li>Verbraucht eines der begrenzten abgeleiteten Felder Ihres Kontos. Wenn eine Komponenteneinstellung denselben Auftrag ausführen kann, sollten Sie dies stattdessen vorziehen.</li></ul> |
| **SQL** | <ul><li>Nicht beschränkt durch die Funktions- und Operatorbeschränkungen, die für abgeleitete Felder gelten.</li><li>Hat keine Auswirkungen auf die Leistung der Daten-Feed-Bereitstellung.</li></ul> | <ul><li>Wird angewendet, nachdem Ihr Daten-Feed bereits bereitgestellt wurde.</li><li>Logik gilt in Analysis Workspace nicht, daher müssen Sie sie dort separat duplizieren.</li><li>Einige Umwandlungen, insbesondere solche, die von einer Bereichseinstellung abhängen, die eine URL analysieren oder einen Wert deduplizieren oder über einen Bereich hinweg beibehalten, sind schwierig oder nicht praktikabel zu replizieren.</li></ul> |

### Auswirkungen der Bereichseinstellungen auf Daten-Feeds {#scope-settings}

Datumsmathematik, Deduplizierung, Nächstes oder vorheriges Datum und Zusammenfassen hängen von einer [!UICONTROL **Umfang**]-Einstellung von Ereignis, Sitzung oder Person ab (die verfügbaren Optionen variieren je nach Funktion). Die Tiefe hat kein konfigurierbares Feld für den Umfang, ist jedoch inhärent an die Sitzung gebunden, ähnlich der standardmäßigen Dimension „Ereignistiefe“. Jedes Feld mit einem Bereich schreibt denselben Wert in jede Zeile innerhalb dieses Bereichs. Dieser Wert hängt von den Daten innerhalb des Lookback-Datumsbereichs ab.
<!-- Open question as of 2026-09-09: is the lookback date range boundary anchored to a fixed point (e.g., midnight), or does it float with the feed run time, and is this configurable? Pending confirmation from Ron Fulkerson. -->

Da der [Lookback-](/help/components/exports/cja-data-feeds/create-feed.md#data-feed-lookback-date-range) bei jedem Daten-Feed-Versand vorgeschoben wird, kann dasselbe Feld bei einem späteren Versand einen anderen Wert zurückgeben, auch für Ereignisse, die bereits aufgetreten sind.

Das Risiko steigt mit der Größe des Umfangs: Der Umfang einer Person ist mit mehr Risiko verbunden als der Sitzungsumfang, da die Historie einer Person innerhalb eines Feed-Durchgangs keine natürliche Zeitgrenze hat.

## Abgeleitete Feldfunktionsvorlagen

[Funktionsvorlagen für abgeleitete Felder](/help/data-views/derived-fields/derived-fields.md#templates) ermöglichen es Ihnen, schnell ein abgeleitetes Feld für einen bestimmten Anwendungsfall zu erstellen, z. B. zum Erstellen von Marketing-Kanälen, zum Erkennen von Bots oder zum Extrahieren eines UTM-Parameters aus einer URL. Da eine Vorlage aus einer Kette vordefinierter Regeln erstellt wird, ist es fast immer vorzuziehen, eine Vorlage zu verwenden, anstatt dieselbe Logik von Grund auf in SQL zu reproduzieren.

Wenn eine Vorlage eine Funktion enthält, die von einer Bereichseinstellung abhängig ist, erbt die Vorlage die Bereichsvorsicht dieser Funktion. Siehe [Wie sich Bereichseinstellungen auf Daten-Feeds auswirken](#scope-settings).
